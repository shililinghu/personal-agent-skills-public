# 实际缺陷沉淀：循环导航、存档恢复、有效消费者和按钮状态

来源：2026-10-23 Juniper’s Greenhouse v11 的源码、实际浏览器触摸和 HTTP 故障审查。沉淀的是可复用的风险链；该游戏的问题不等于其他游戏也有问题。review 仍只检查，不能据本页自动改产品。

每次逻辑检查自动执行 `logic_check.py --init`，它保留已有 F01–F20 结果并补齐 `regressions` 中 R01–R08。随后运行 `--mode review/build`，脚本同时审查旧流程、新回归、证据文件哈希及当前源码/运行配置绑定。旧记录缺新回归时会显示 missing；新增项不测不能沿用旧的“全部通过”。

## 每次要检查的八条链

| ID / 规则 | 适用机制与必须观察 | 自动检查与边界 |
|---|---|---|
| R01 / L-CYCLIC | 皮肤、商店、地图、背包等循环列表：按实际项目列清单，正反向各至少 3 圈；覆盖空、单项、多项边界（不可到达的用隔离数据验证并说明）；箭头、当前项和购买/装备入口始终可用 | 扫描 `(index + length) % length` 疑点。JS 负余数可能仍为负；完整归一化或已证明的游标边界可判误报。需要读源码和真实翻页，不能只修一个列表 |
| R02 / L-SAVE-RECOVERY | 正常旧存档、坏 JSON、缺字段、错误类型、负值/越界分别启动；保留可用字段，旧原文有备份，错误页 Retry/恢复按钮真正有效 | 自动提示保存 JSON 读取位置。catch、schema 数字和 Retry 文字不能证明恢复；禁止为了测试清正式存档。字段名不同不要求统一结构 |
| R03 / L-LOAD-RETRY | 真实图片/分包传输挂起，出现 Retry 后只放行未来请求，旧请求继续挂起；记录同一资源底层请求数及身份、ready 和实际关卡操作。另测 SDK 回调与原定时器同时被扣、旧结果、明确失败和正常对照 | 扫描加载 interval 疑点。完整矩阵仍按 [加载恢复](../../cocos-game-to-english/references/loading-recovery-regression.md) 和 `audit_loading_recovery.py`，不再建第二套加载协议。HTTP 503 恢复通过不覆盖挂起请求合并问题；Web 与 Native 分层 |
| R04 / L-CONSUMER | 提示、撤销、复活、补给等每个消耗入口：从首页/地图/设置/结算/退出后进入，确认无有效局时不扣资源；有效局内只扣一次且效果落在当前消费者；关闭/重复/迟到不误扣 | 读取扣费链与页面/局次守卫，真实比较“资源前后＋棋盘/效果前后”。扣费成功本身不是通过；没有消耗机制可 n/a |
| R05 / L-EXIT | 失败页固定 Home＋Retry，额外广告独立；暂停 Continue/Restart/Home；胜利 Next/Home；设置/弹窗可返回。两种比例实际点击，记清 Home 是首页还是地图，Restart 是否收费 | 不能从源码里出现 HOME/RETRY 字符串推断当前状态有这些键。× 可返回时准确报告“缺明确出口”，不能夸大成完全卡死。按真实机制实现重开，不为无局内状态的产品硬造暂停 |
| R06 / L-BUTTON-EFFECT | 每页每状态从运行 UI dump 建按钮清单，包含条件不足、已领取等禁用态，尤其共享 HUD 在不同玩法里的 Undo/Go/Restart。点击要产生正确业务结果或明确的拒绝/不可用反馈；弹窗关后原位置恢复输入 | 点击音效、动画、clicked 回执不证明功能成功。已装备物品重复装备、页首上一页等合法无变化须有可见边界/状态说明，不机械算缺陷；不支持的工具隐藏/禁用即可，不强加功能 |
| R07 / L-POINTER | 按实际输入政策：单指拖动中加入第二指，第二指移动/抬起/取消不能覆盖或清掉主指；主指取消不提交，之后新手势可用 | 检查已有 pointer 时 TOUCH_START 是否直接覆盖。需要真实多触点与 cancel 事件；单点 tap 不覆盖多指。游戏若有有意多指机制，按其明确规则测试，不强制单指 |
| R08 / L-RUNTIME-DATA | 列实际运行加载的数据路径与数量，现有测试是否读同一批配置；所有当前配置可加载、无空槽、解法/状态可重演；浏览器抽样与离线全量范围分别记录 | 测试日志“100关通过”不能证明当前70关导出正确；不追认附件自报的断言数。当前脚本/JSON 指纹绑定防止沿用源码改变前的观察，但不替代 Web/Native 构建绑定 |

## R05 补充：关闭出口必须验结果（2026-10-25）

从大厅和局内打开，切到声音等子页并修改选项后，按玩家看到的位置真实触摸关闭；至少覆盖中心及按钮内偏心点，触摸区不小于44×44 CSS像素（按当前相机/缩放计算），层级不被内容遮挡。断言弹窗与遮罩实际消失、暂停解除、底页一次操作生效，再关闭重开；不能点后直接reload/换页掩盖失败。换图/适配/公共按钮改动后旧观察失效，只复查受影响出口。针对反馈的故障输入保留旧版失败、新版通过及中心正常对照；未在当前运行层复现要如实写，不能拿扩大热区冒称已证实设备根因。

## R06 补充：禁用态不能漏测（2026-10-25）

公共触点/前后台恢复也属于R06适用范围；`button_state_check.py` policy 2强制输入生命周期适用声明、每共用绑定的缺终止事件轨迹与恢复后的真实业务结果。缺项不得通过；当前源码与轨迹回读校验，具体字段与局部触发边界见下方共用参考。

按[按钮状态轻量核对](../../cocos-game-to-english/references/button-state-check.md)执行：从业务规则及运行界面列本轮控件×适用状态，保留 disabled；同一 `button_state_check.py` 核计划与实际结果、业务预期与正确反馈、资源保护。局部维护直接运行，不扩无关CI；完整R06引用同一报告 `button_check: {path, sha256}`，门禁重读原输入，概括文字和泛化n/a不能代替。

共享组件换图、透明度或命中修改覆盖受影响调用方及关闭重开。旧故障版须失败，正常禁用态与修复版通过；未到达状态保留未测，生产方法隔离回放明确标层级。提示实际看图，不能以节点存在代替可读。`disabled_state_outcomes` 只作摘要，逐项判据以结构化报告为准。Milos原故障：未达条件提前return无监听，提亮后未复测。

## 记录格式与门禁

`flows.json` 继续保留原 `flows`，增加 `regression_binding` 和 `regressions`。`--init` 自动生成未测项和当前 `source_sha256`，不会覆盖已测结果，也不会偷偷把旧绑定改成当前绑定。

每项可写 `pass / fail / untested / n/a`：

- `pass` 必须含该项允许的 `layer`、逐字段的具体 `observations`、非空 `evidence` 文件 `{path, sha256}`；字段列表和允许层级由 `logic_regressions.py:CASES` 定义，脚本直接输出缺哪些字段。
- `n/a` 写真实无此机制或本次用户明确限定的范围原因，不能因为难测/没测而 n/a。用户限定范围时报告仅为局部完成，不能用整表 n/a 宣称全游戏通过。
- 文件哈希变更、来源绑定过时、重复 ID、仅写 true/pass/已测、证据为空或只拿静态源码代替需触控的案例，均不通过 build。review 正常输出问题，不改游戏。
- `layer` 是证据边界：`browser_touch`、`browser_fault`、`production_data_replay`、`mixed_runtime`。`mixed_runtime` 要在观察中逐段说明 Web、Native受控边界和离线部分；不能把命名当成真机证明。静态与隔离结果只补充需要浏览器观察的项。
- 更新绑定前先确认哪些源码/运行配置改变，重跑受影响链，未受影响结果须有可审查的保留理由；不能只改哈希迁移旧 pass。脚本只校验记录、完整性与绑定，不能识别伪造文字，主 Agent 必须读原始证据。

声音设置按[声音状态交叉检查](../../cocos-game-to-english/references/common-game-components.md)核OFF/零档/恢复及显示、增益、存档一致；不得仅验开关方法或存档键。

源码声音设置检测新增边界：`setItem(SAVE_KEY, JSON.stringify(state))` 或间接 JSON 整体状态写入可能保存音量开关，不能因存档键不含 sound/music 就说只在内存。追踪真实 writer，并刷新读回、验证后加载音频的应用结果。

自测：`python3 ../cocos-game-to-english/scripts/test_logic_regressions.py`。它用临时合成工程校准漏项/旧证据拒绝，不代表任何实际游戏通过；临时目录自动清理。

## 2026-10-23 增补：空存储和空功能

R02 新增 observations：native_missing_key_semantics（null/undefined/空字符串及真实类型）、actual_reward_ledger_and_adapter（实际 source/Native 路径和指纹，旧版负对照）、storage_failure_diagnostics（parse/schema/checksum/read/write 分层原因）。R06 新增 nonfunctional_legacy_entries_removed：原 UI 空实现、空排行榜等删除及邻接布局/返回验证。无相关机制或用户限制范围时逐项说明，不能用新功能测试代替原有账本。旧 pass 缺新字段不得沿用。细则见 [案例](../../cocos-game-to-english/references/native-reward-storage-and-empty-features.md)。

## R04 补充：道具效果闭环（2026-10-26）

道具/广告效果故障先保存准确包与使用前后同一局数据，比较约定增量、实际HUD及入口状态，再执行一次合法玩法输入；广告关闭、到账回执、内存值或按钮消失均不能单独判通过。隔离联合测试不得用HUD/关闭/输入替身冒充实跑。已报告故障在局部链路闭合前不得被ZIP通过覆盖；同判据应拒绝丢效果/重复应用反例并接受正常结果。录像显示正确增量时仅说明数值分支未复现，仍核玩家能否感知成功；缺使用前值时先补证。收到“数值已加却像没生效”的反馈时，核短时可读的获得量/前后值、消退后的已用态与下一次操作；取消/失败不得出现成功提示。数值正确不能关闭反馈缺陷，旧版缺提示应被同一可见判据拒绝。具体项目证据留工程，不写入通用Skill。

### 路径画面与判定一致（2026-10-26）
滑块/管道/寻路类：可见开口、起终点朝向、连接判定、提示解与移动动画必须使用同一方向语义。对当前实际加载的全部关卡重演合法解，并独立按可见端口检查相邻双向连通、端点、单向格的入口/出口、边界和必经物；不能用同一判定器自证。动画从真实起点沿合法通道走，禁止从默认坐标飞入、穿越封口或直线抄近路；结束后才结算。共用绘制器/皮肤/页面一并覆盖，离线全量与真实触摸范围分别报告。先以原故障版证明同一检查失败，再验修复；只进关不算路径玩法通过。Ziggy R36：判定把起点 dir 反向、终点按行进方向解释，绘制却按开口；旧解法重演仍可成功，因此仅查有解漏报。
